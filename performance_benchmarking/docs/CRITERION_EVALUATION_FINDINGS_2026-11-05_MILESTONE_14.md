# Criterion Evaluation Findings — Milestone 14

Date: 2026-11-05
Task: ASM-068 — local criterion evaluation and IMRAD reporting

## Findings Summary

The application now supports a separate local-model inference pass that evaluates each user-supplied criterion as pass or fail and returns a rationale. The criterion pass percentage is the number passed divided by the number evaluated. It is stored separately from normalized exact-match scoring. The results interface shows the percentage and individual judgments, and its IMRAD print report opens with a findings summary and ends with a conclusion.

Automated verification completed successfully: 33 Python tests, 1 browser UI test, Python compilation, JavaScript syntax validation, and `git diff --check`.

## Methods

The answer is generated by the configured answer model. If criteria are supplied and local inference is enabled, the controller makes a second Ollama request using the selected evaluator model (the answer model by default). The judge receives the original source, question, generated answer, and each criterion. Its JSON response must contain one boolean judgment and a rationale for every criterion. Invalid or incomplete output is recorded as an evaluation error; no pass percentage is reported for that run.

The run record includes evaluator model/version, prompt and completion token counts, judge elapsed time, per-criterion results, and the pass percentage. Overall execution time includes the evaluator pass. Paired-run equivalence checks include criteria and evaluator settings. CSV, dashboard, and PDF output preserve criterion results separately from exact match.

The PDF findings summary reports aggregate criterion counts and percentage alongside exact-match and run counts. Detailed results include criterion wording, judgment, rationale, evaluator, strategy, and repeat. Discussion labels criterion judgments as model-judged rather than gold-standard. The conclusion summarizes the available recorded measures and avoids a quality claim when scored data is absent.

## Limitations

The judge receives the full original source. Long documents can exceed the selected local model's context window. The controller records the evaluation error and leaves the percentage unavailable rather than substituting a score. The judge itself can make mistakes; the percentage measures agreement with supplied criteria as judged by that model, not independently verified answer quality.

## Conclusion

ASM-068 is implemented and verified at the software level. Users can supply independent criteria, inspect a separate local judge's pass/fail decisions and rationales, and view the resulting percentage in the interface and IMRAD PDF report. Use representative papers and human-reviewed judgments to assess evaluator quality before interpreting criterion percentages as evidence about answer quality.
