# ASM and No-ASM Benchmark Findings — 2026-11-05 — Milestone 13

This report records the no-ASM language benchmark implementation, its corrected measurement batch, and the IMRAD results-report feature. Earlier reports remain unchanged; see [Milestone 11 language findings](LANGUAGE_BENCHMARK_FINDINGS_2026-11-05_MILESTONE_11.md) and [Milestone 12 final verification](PROJECT_VERIFICATION_2026-11-05_MILESTONE_12.md).

## Benchmark methods

Each JavaScript, C, Go, and Rust implementation now runs two strategies on each shared fixture:

- **ASM:** question-term retrieval, address lookup, and evidence expansion under the fixture budget.
- **No ASM (source-prefix baseline):** concatenate original fragment text in fixture order, then retain the prefix through the final ASCII word token that fits the same evidence budget. Retrieval, address lookup, and expansion are skipped. Output includes no retrieved addresses, lookups, or expanded fragments.

The correctness gate compares each implementation with the expected strategy output before accepting timing records. The completed v2.0 batch used the three existing fixtures, two warmups, and five measured repetitions per fixture/language/strategy combination. That produced 120 accepted measurements (3 fixtures × 4 languages × 2 strategies × 5 repetitions). All records are appended to `data/results/language_benchmarks.jsonl`; historical records remain available.

Toolchains: Node v25.9.0; GCC 11.2.0 with `-std=c11 -O2 -Wall -Wextra -Werror`; Go 1.17 with `go build -trimpath`; Rust 1.99.1 with `--edition=2021 -C opt-level=3 -C codegen-units=1 --target x86_64-pc-windows-gnu`.

## Results

The table reports the median internal runtime across all three fixtures (15 measured runs per language/strategy). This is a descriptive aggregation of the checked-in small, medium, and large fixture set.

| Language | ASM median (ms) | No-ASM median (ms) | ASM samples | No-ASM samples |
|---|---:|---:|---:|---:|
| C | 0.2134 | 0.2097 | 15 | 15 |
| Go | 0.2399 | 0.2274 | 15 | 15 |
| JavaScript | 0.9037 | 0.8500 | 15 | 15 |
| Rust | 0.2517 | 0.2449 | 15 | 15 |

The measured no-ASM path was faster by these medians on this machine and fixture set. The gaps are small, and these results do not establish a general performance conclusion. The browser dashboard plots each strategy separately and keeps per-operation measurements, unavailable metrics, and revisions distinct.

## Preserved pilot records

An earlier v1.9 trial also emitted 60 records labeled no-ASM. Review found that JavaScript, Go, and Rust still calculated question-fragment retrieval before entering their source-prefix branch. The whole v1.9 baseline group is preserved in the JSONL history and explicitly marked `measurement_validity: rejected`, because strategy conditions did not match across languages. Charts and PDF summaries exclude those rows and state why. The v1.9 ASM records remain usable. A corrected v2.0 implementation branches before ASM retrieval, and its complete batch passed correctness checks. No historical measurements were deleted.

## Limitations

The benchmark uses only three small fixed fixtures and short in-process operation timings. The no-ASM path represents a simple source-prefix truncation baseline, not every possible non-ASM retrieval strategy. Model answer scoring remains normalized exact match. The PDF is generated by the browser print system, so PDF creation and filename selection happen in its print dialog.
